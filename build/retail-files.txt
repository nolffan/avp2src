## The retail games the build takes its data from: Aliens versus Predator 2
## (Europe) with its English 1.0.9.6 patch (avp2-eu-1.0.9.6), and Primal
## Hunt (Europe) 1.0.2.2 (avp2-ph-eu), as their setups install them from
## their three discs. This list holds no game data. It tells build/discs.py
## which bytes of which disc make each file, and what each file must be
## (its size and SHA-256). build/mkinstall.py reads it too, for the install
## scripts of a public archive.
##
## D <id> <volume label> <volume blocks> <image size> <image SHA-256> <image name>
##   One disc. A disc image is recognised by its volume label and its volume
##   size (blocks of 2048 bytes). The image size, SHA-256 and name are those
##   of one known good image (the .iso of the redump dump). Another correct
##   copy of the disc can have another size and SHA-256: each file is checked.
## M <id> <disc> <offset> <size> <SHA-256> <path on the disc>
##   The 1.0.9.6 patch's payload: the one folder of the Microsoft cabinet at
##   that offset of the disc's image, unpacked; its size and SHA-256.
## S <name> <id> ...
##   A set of discs the games install from (the first that is complete).
## F <release> <path> <size> <SHA-256> <origin>
##   One installed file: its release, its path in the install, its size and
##   SHA-256, and where it comes from (disc, or update: the patch).
## W <sets> copy|is <id>:<offset>:<length> ...
##   A way to read the file above in those sets: the byte ranges (of a
##   disc's 2048-byte-sector image, or of the payload), joined, are the file
##   (copy), or its InstallShield 6 cabinet data (is: chunks, each a 16-bit
##   length and a raw deflate stream).
## The fields are separated by one TAB.
